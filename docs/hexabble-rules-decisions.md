# Hexabble rules decisions (versioned)

Current rules version: **`hexabble-rules-1.0`** (engine `src/games/hexabble/engine/`, constant `RULES_VERSION`).

`hexabble-rules-1.0` is a semantic migration of the adapted reference engine
(`reference/build-pack-v3/ui/hexabble/engine.js`, pack fixtures pinned to `hexabble-integration-1.0`).
The originating rules PDF is not in the pack, so where the source is silent or ambiguous the
source code's actual behaviour is kept, written down here, and covered by a named test.
Any change to a decision below needs a new rules version; saved matches pinned to another
rules version are refused on restore with an explanation (they are set aside, not deleted).

| ID | Topic | Decision in 1.0 | Test (src/games/hexabble/engine/) |
|---|---|---|---|
| R0 | Source semantics | Board (217 cells, radius 8, axial), premium layout, tile catalogue (98 letters, 4 Wild, 2 Key, 4 Pivot, source IDs t0..t107), reading directions, adjacency rules, additive word multipliers, bingo +50, exchange threshold, end conditions and final adjustments are copied unchanged. | pack.test.ts (18 ported pack checks) |
| R1 | Scoreless turns | **Exchanges count** as scoreless turns, together with passes and failed challenges. The match ends after 2 x players consecutive scoreless turns. This is the source engine's behaviour; the original README mentioned only passes and failures. The rules text says so explicitly. | rules.test.ts "exchanges count as scoreless turns", "failed challenges count" |
| R2 | Checking modes | The source's `official` mode is named `challenge` in state and UI ("Challenge checking"). Friendly: word errors block the move with no penalty. Challenge: a move with a word error is recorded as a zero-score turn, the rack is kept and play passes on. Placement (geometry) errors never cost a turn in either mode. Neither mode is described as an official tournament ruleset or as a difficulty level. | pack.test.ts Friendly/Challenge checks |
| R3 | Ambiguous main word | When a move can be read more than one way (a single tile forming words in several directions, or several Pivot paths), every reading is evaluated and ranked: fully legal first, then readings with only word errors, then placement errors; within a rank the higher score wins; exact ties keep the order down, down-right, up-right (and Pivot permutation order). The chosen reading is what the preview shows and what is committed. | rules.test.ts "ambiguous main-word choice" |
| R4 | Pivots | A Pivot must sit between two letters of the same word, the word must change reading direction at every Pivot, every segment (before, between, after Pivots) must contain at least one letter, and all tiles placed must lie on that path. Pivots score 0, trigger no premium, store no letter and remain a void: later words cannot read through them and they do not count as neighbours. A Pivot counts as one of the seven tiles for the +50 bonus. | rules.test.ts "Pivots" block |
| R5 | Keys | While any Key space is free, each Key placed must go on a free Key space (a move may place more Keys than there are free spaces only if every free space receives one). A Key on a free Key space may start a word that does not join existing tiles, including as the opening move instead of the centre. A letter tile on a Key space scores the double word but never grants an island. Once all six Key spaces are covered, a Key is an ordinary Wild and must connect like any tile. | rules.test.ts "Key tiles and Key spaces" |
| R6 | Centre after a Key opening | If the match opened on a Key space, the centre remains a free start space: a later word covering the free centre may also stand alone. Source behaviour, kept; flagged in REVIEW-LOG for a rules owner. | covered by the connection rule in analyse.ts |
| R7 | Three-Tile Adjacency Rule | Counts committed neighbouring letters only (not tiles placed in the same move; Pivots excluded). Such a tile must form a valid word, other than the main word, with one of them. | rules.test.ts "Three-Tile Adjacency Rule" |
| R8 | Adjacent Letters Rule | Two-letter touches score when valid and are ignored when invalid; each new tile may have at most one ignored touch. Lines of three or more letters must always be valid. Every counted word gets its own premium derivation from newly covered cells. | rules.test.ts "Adjacent Letters Rule", "own derivation per word" |
| R9 | Boundary guards | Rejected atomically with stable codes: duplicate rack IDs in one move (`duplicate-tile`), non-integer coordinates (`bad-coordinates`), special faces that are not exactly one letter A–Z (`bad-face`), tiles not in the active rack (`not-in-rack`). A face supplied for a letter or Pivot tile is ignored (normalised to none) rather than rejected, as in the source. | pack.test.ts, rules.test.ts "boundary validation" |
| R10 | Randomness | Bag order comes from a seeded mulberry32 generator whose state (one uint32) is stored in the match. The UI draws the initial seed from `crypto.getRandomValues`. Exchanges reshuffle the whole bag with the stored state, as the source did with its RNG. | rules.test.ts "same seed", snapshot.test.ts "generator state" |
| R11 | Dictionary | Words are checked against the ESDB GB candidate membership (`gb-esdb-v1-candidate`, docs/DECISIONS.md D4), not the 252,209-entry merged list. Some two-letter tile-game words (for example QI, ZA, AA, AE, AI) are therefore not accepted, while a few abbreviations (CF, JR) are. The version is pinned in each saved match; a match restored under a newer list continues (committed words stand). | validate.ts checks the pack fixtures against the production list |
| R12 | Manual end | End game (after confirmation on the shared device) ends the match by agreement: everyone loses unplayed tile values, nobody gains. It is idempotent. | pack.test.ts "manual end" |
| R13 | Going out | A player who plays their last tile while the bag is empty ends the match and gains the total of everyone else's unplayed tiles; the others lose their own. The +50 bonus can apply on the same move. Ties list every winner. | rules.test.ts "ending and final adjustments" |
| R14 | Rack order | Rack order is part of the match (so a refresh restores it). Shuffle and reordering are an `arrange` action that does not use the turn. | rules.test.ts "rack arrangement" |
